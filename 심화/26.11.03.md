# [UiPath 심화] Config와 Dictionary, 로그인 정보 분리하기

## 1. 학습 주제

URL이나 파일 경로를 액티비티마다 직접 적으면 값 하나를 바꿀 때 여러 곳을 수정해야 한다. 오늘은 설정을 Config.xlsx로 모으고, Dictionary에 담아 필요한 곳에서 꺼내 쓰는 흐름을 정리했다.

로그인 정보는 Config에 비밀번호를 적는 대신 Windows 자격 증명과 연결한다.

## 2. Config.xlsx에 넣는 정보

계정 참조 정보, 경로, 코드, 이메일 관련 설정을 구분해 관리한다.

| 설정 | 예시 |
|---|---|
| 브라우저 주소 | 접속할 업무 사이트 URL |
| 파일 경로 | 입력 파일 위치, 결과 저장 폴더 |
| 코드 | 업무에서 사용하는 코드나 파일명 |
| 계정 참조 | Windows 자격 증명을 찾을 때 사용할 이름 |

Config는 실행 전에 읽어 둘 설정이다. 처리 대상 주문이나 고객 목록을 담는 업무 데이터와는 역할이 다르다.

## 3. Dictionary는 키로 값을 찾는 자료형

DataTable이 행과 열로 데이터를 담는다면 Dictionary는 Key와 Value를 한 쌍으로 담는다.

```text
System1_URL   → 접속할 사이트 주소
System1_Login → 자격 증명에 등록한 대상 이름
```

`Dic_Config` 변수 형식은 `Dictionary(Of String, Object)`이다. 키는 문자열이고, 값은 Object로 받는다.

변수를 선언한 뒤에는 Dictionary 객체를 만들어야 한다. 기본값이나 Assign의 값에 다음 표현식을 넣는다.

```vb
New Dictionary(Of String, Object)
```

선언만 하고 값이 Nothing인 상태에서 항목을 넣으려고 하면 참조 오류가 발생한다. 변수를 만드는 것과 실제로 사용할 객체를 만드는 것을 구분해야 한다.

## 4. Excel에서 읽은 값을 Dictionary에 저장

1. `Dic_Config`를 선언하고 초기화한다.
2. Read Range Workbook으로 Config.xlsx의 `Path` 시트를 읽는다.
3. 결과를 `DT_Config`에 저장한다.
4. For Each Row in DataTable로 행을 순회한다.
5. `Name` 열은 키로, `Value` 열은 값으로 저장한다.

Assign은 다음처럼 연결한다.

| 항목 | 표현식 |
|---|---|
| 저장할 대상 | `Dic_Config(CurrentRow("Name").ToString)` |
| 저장할 값 | `CurrentRow("Value").ToString` |

이후 URL을 사용할 때는 아래처럼 키로 접근한다.

```vb
Dic_Config("System1_URL").ToString
```

Dictionary의 값 형식이 Object여도 위 예제는 저장할 때 `.ToString`을 사용했으므로 문자열이 들어간다. 숫자로 계산할 설정은 사용할 때 필요한 형식으로 변환해야 한다.

## 5. 빈 키와 중복 키 확인

Excel에 빈 행이 섞여 있을 수 있으므로 Name 열을 먼저 검사한다.

```vb
String.IsNullOrWhiteSpace(CurrentRow("Name").ToString)
```

조건이 True이면 건너뛰고, False일 때 Dictionary에 저장한다.

| 값 | IsNullOrEmpty | IsNullOrWhiteSpace |
|---|---|---|
| Nothing | True | True |
| 빈 문자열 | True | True |
| 공백만 있는 문자열 | False | True |
| 일반 문자열 | False | False |

빈 셀처럼 보이지만 공백이 들어 있는 경우까지 확인하려면 IsNullOrWhiteSpace가 맞다.

중복 키도 주의해야 한다. `Dic_Config(key) = value` 방식은 기존 키가 있으면 값을 덮어쓴다. 반면 `Add`로 같은 키를 다시 추가하면 예외가 발생한다. 같은 키를 두 개 보관하는 구조가 아니다.

필수 설정을 읽기 전에는 키 존재 여부도 확인할 수 있다.

```vb
Dic_Config.ContainsKey("System1_URL")
```

키가 있다는 것과 값이 올바르다는 것은 별개다. URL 키가 있어도 Value가 비어 있다면 초기 설정 단계에서 확인할 필요가 있다.

## 6. Windows 자격 증명 연결

Windows 자격 증명 관리자의 일반 자격 증명에 로그인 정보를 등록한다. Config에는 이 정보를 찾을 대상 이름을 넣는다.

다음은 이름 관계를 정리한 예시다.

```text
Config의 키: System1_Login
Config의 값: System1_Account
Windows 자격 증명의 대상 이름: System1_Account
```

이때 Get Secure Credentials의 Target에는 다음 값을 전달한다.

```vb
Dic_Config("System1_Login").ToString
```

여기서 전달되는 것은 `System1_Login`이라는 키 자체가 아니라, 그 키에 저장된 `System1_Account`이다. 설정 이름이 비슷해서 이 부분을 구분해서 봐야 한다.

## 7. 로그인까지 이어지는 흐름

```text
Config.xlsx 읽기
→ Dictionary 구성
→ 자격 증명 대상 이름 조회
→ Get Secure Credentials
→ Username과 Password 받기
→ 로그인 화면에 입력
```

Credentials 패키지를 설치하고 Get Secure Credentials의 출력에 Username과 Password 변수를 연결한다. Password는 보안 문자열로 받아 이를 지원하는 비밀번호 입력 속성에 연결한다.

복습용 로그에는 비밀번호를 출력하지 않는다. 로그인 여부를 확인하는 데 비밀번호 원문까지 필요하지는 않다.

## 8. 복습 메모

설정이 바뀌는 위치와 사용하는 위치를 나눠 두면 수정할 곳을 찾기 쉬워진다. 다만 Config로 옮겼다고 설정 오류가 없어지는 것은 아니다. 빈 값, 오타, 중복 키는 읽는 단계에서 확인해야 한다.

다시 정리할 내용은 세 가지다.

- Dictionary를 초기화해야 하는 이유
- Config의 키와 자격 증명 대상 이름의 차이
- 로그인 실패 시 Config 값과 자격 증명 이름을 확인하는 순서
