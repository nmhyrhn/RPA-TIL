# [UiPath 심화] 워크플로우 분리와 재사용, 인수부터 라이브러리까지

## 1. 학습 주제

로그인, 목록 추출, 상세 페이지 이동을 한 파일에 계속 추가하면 전체 순서를 읽기 어려워진다. 오늘은 작업별로 워크플로우를 나누고 인수로 데이터를 주고받는 방법을 정리했다.

재사용 기능도 용도가 다르다. Invoke Workflow File, Library, Snippet, Object Repository를 각각 언제 쓰는지 구분했다.

## 2. Invoke Workflow File

Invoke Workflow File은 다른 `.xaml` 파일에 작성한 작업을 호출하는 액티비티다.

예를 들어 Main.xaml에서 전체 순서를 관리하고, 세부 작업은 아래처럼 나눌 수 있다. 파일명은 역할을 설명하기 위한 예시다.

```text
Main.xaml
  → Login.xaml: 로그인
  → GetWorkItems.xaml: 목록 추출
  → OpenDetail.xaml: 상세 페이지 이동
```

호출할 파일을 정하는 것만으로 끝나지는 않는다. 그 파일에 어떤 데이터를 전달하고, 어떤 결과를 받을지도 연결해야 한다.

## 3. 변수와 인수의 차이

변수는 워크플로우 안에서 데이터를 보관한다. 인수는 호출하는 워크플로우와 호출받는 워크플로우 사이에서 데이터를 전달하는 데 사용한다.

방향은 호출받는 파일 기준으로 읽으면 이해하기 쉽다.

| 방향 | 의미 | 예시 |
|---|---|---|
| In | 외부에서 값을 받는다 | 이동할 URL |
| Out | 처리한 결과를 외부로 전달한다 | 추출한 DataTable |
| In/Out | 값을 받아 사용한 뒤 다시 전달한다 | 호출 전후로 이어서 사용할 데이터 |

Main에 있는 변수와 하위 파일의 인수 이름이 같아야 하는 것은 아니다. 호출부에서 알맞은 변수와 인수를 연결하는 것이 중요하다.

## 4. 목록 추출 결과를 Main으로 전달

ACME의 Work Items를 추출하고 Type이 `WI5`인 항목의 상세 페이지로 이동한다.

목록 데이터를 밖으로 꺼내는 흐름은 다음과 같다.

```text
하위 워크플로우
  Extract Table Data
  → 추출 결과를 DataTable 변수에 저장
  → Out_WorkItem 인수에 할당

Main.xaml
  Invoke Workflow File
  → Out_WorkItem을 Main의 DataTable 변수에 연결
```

Out 인수에 결과를 넣어도 호출부의 연결이 빠지면 다음 단계에서 쓸 변수를 제대로 받지 못한다. 인수를 추가하거나 바꿨다면 Invoke Workflow File의 인수 가져오기와 연결 상태를 같이 확인해야 한다.

또한 Main의 DataTable 변수가 추출 단계와 반복문 양쪽에서 보이는 범위에 있어야 한다.

## 5. 상세 페이지 이동은 URL을 입력받도록 분리

상세 페이지 이동용 워크플로우는 String 형식의 `In_URL`을 받고, Go To URL에 연결한다.

```text
WI5 항목만 필터링
→ For Each Row in DataTable
→ 현재 행의 WIID 확인
→ 상세 주소 구성
→ In_URL에 전달
→ 상세 페이지 이동
```

이렇게 나누면 이동용 파일은 현재 항목이 몇 번째 행인지 알 필요가 없다. 전달받은 주소로 이동하는 역할만 맡는다.

기존 브라우저에 연결하도록 열기·닫기 옵션을 Never로 설정한다. 이 경우 앞 단계에서 브라우저가 준비되어 있어야 한다. 페이지 제목이 바뀔 수 있는 부분은 셀렉터를 조정하되, 다른 창까지 잘못 잡지 않는지도 확인해야 한다.

## 6. Library와 Snippet의 차이

| 기능 | 사용 방식 | 수정 후 확인할 점 |
|---|---|---|
| Invoke Workflow File | XAML 파일을 호출 | 인수 연결과 호출 대상 |
| Library | 공통 기능을 패키지로 게시하고 설치 | 패키지 버전과 사용하는 프로젝트의 업데이트 |
| Snippet | 자주 쓰는 액티비티 묶음을 삽입 | 이미 삽입한 부분은 따로 수정 |
| Object Repository | UI 대상 정보를 등록하고 참조 | 요소 변경, 참조와 동기화 상태 |

여러 프로젝트에서 공통 기능을 관리하려면 Library가 어울린다. 개발할 때 반복해서 넣는 작업 틀이 필요하면 Snippet을 사용할 수 있다.

Snippet은 넣는 시점의 복사본으로 생각하면 된다. 원본 스니펫을 고쳤다고 이미 삽입한 모든 워크플로우가 함께 바뀌지는 않는다.

## 7. 문자열 처리 라이브러리 예제

상세 화면의 텍스트에서 ID, Name, Country를 분리한다.

예를 들어 아래 문자열이 들어온다고 하자.

```text
ID: A001
Name: Kim
Country: Korea
```

첫 번째 줄의 값은 다음 방식으로 추출한다.

```vb
In_FullText.Split(vbLf, StringSplitOptions.RemoveEmptyEntries)(0).Split(":"c)(1).Trim()
```

표현식을 나누면 다음과 같다.

1. 줄바꿈으로 나눈다.
2. 빈 문자열은 결과에서 제외한다.
3. 첫 번째 줄을 선택한다.
4. 콜론으로 나눈 뒤 두 번째 조각을 가져온다.
5. 양쪽 공백을 제거한다.

이 식은 줄 순서와 콜론이 있다는 전제에 의존한다. 입력 형식이 달라지면 잘못된 값을 가져오거나 인덱스 오류가 날 수 있다. 공통 라이브러리로 만들 때는 어떤 형식의 문자열을 받는지부터 정해야 한다.

라이브러리는 게시 후 사용할 프로젝트에서 패키지 경로를 등록하고 설치한다. 기능을 수정했다면 게시한 버전과 사용하는 버전도 함께 확인한다.

## 8. Object Repository

Object Repository는 버튼이나 입력창 같은 UI 요소의 대상 정보를 모아 관리한다. 업무 로직 전체를 저장하는 Library와는 역할이 다르다.

여러 액티비티가 같은 로그인 버튼을 참조한다면, UI 변경 시 관련 정보를 한곳에서 관리할 수 있다. 수정 후에는 액티비티가 저장소 요소를 참조하는지, 동기화가 필요한지 확인한다. 라이브러리로 공유한 요소라면 사용하는 쪽의 패키지 버전도 확인해야 한다.

## 9. 복습 메모

워크플로우를 나누는 기준은 파일 개수가 아니라 역할이다. 파일 이름만 봐도 무엇을 하고, 인수만 봐도 무엇을 받는지 읽을 수 있도록 정리하고 싶다.

복습할 때는 `목록 추출 → Out 인수 → Main 변수 → 반복문 → In_URL` 순서로 데이터가 이동하는 과정을 따라가 볼 것.
