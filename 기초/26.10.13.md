# 테이블 추출과 Selector

## 오늘 정리한 내용

웹 표를 DataTable로 전달하고, 선택기와 화면 상태 확인으로 UI 작업을 구성한다.

## 대표 흐름

```text
Flowchart
 ├─ Sequence: 웹 표 추출 → dtRates
 └─ Sequence: Excel 파일 열기 → dtRates를 시트에 출력
```

`dtRates`의 범위는 두 Sequence를 포함하도록 설정한다. 추출 미리보기에서 열 이름과 데이터가 섞이지 않았는지 확인한다.

## 테이블 추출 메모

- 전체 열과 필요한 열만 추출하는 방식을 구분한다.
- 여러 페이지라면 다음 버튼과 마지막 페이지 동작을 확인한다.
- 결과 행 수는 현재 원본과 비교한다.
- 추출과 출력은 별도 작업이며 같은 DataTable을 전달해야 한다.

## Selector 메모

| 항목 | 확인할 내용 |
|---|---|
| 브라우저 범위 선택기 | 페이지 제목 등 변화하는 속성 |
| 액티비티 선택기 | 실제 버튼·입력란 식별 속성 |
| 와일드카드 | 변화하는 부분에만 적용 |
| 강조 표시·유효성 검사 | 의도한 대상인지 확인 |
| Check App State | 대상이 있을 때와 없을 때의 처리 |

## 날짜 표현식

VB 예시:

```vb
DateTime.Now.AddDays(-1).Day
```

전날의 일 숫자만 얻는다. 월초와 연초에는 달력의 월·연도 이동도 필요할 수 있으므로 이 표현식만으로 날짜 선택 전체가 완성되지는 않는다.

## 자주 확인할 문제

- 다른 Sequence에서 변수 인식 실패 → Scope 확인.
- 새 브라우저가 중복 생성 → 로그인·추출 범위와 열기/닫기 설정 확인.
- 팝업이 없을 때 클릭 오류 → 상태 확인 후 분기.
- 와일드카드 적용 후 잘못된 대상 선택 → 고정 속성과 매칭 범위 확인.
- 첫 페이지만 저장 → 페이지 이동 설정과 추출 범위 확인.

## 검증 체크리스트

- [ ] 원본과 저장 결과의 열·행 대응 확인
- [ ] 첫 페이지와 마지막 페이지의 데이터 포함
- [ ] 서로 다른 ACME 화면에서 로그아웃 대상 확인
- [ ] 팝업 유무에 따른 경로 확인
- [ ] 날짜 실습은 월초·연초 조건을 별도로 점검

## 오늘의 정리

테이블 추출은 데이터 구조를 읽는 작업이고 Selector는 화면 대상을 찾는 조건이다. 오류가 발생하면 데이터 문제인지 UI 식별 문제인지 먼저 나눠 본다.
