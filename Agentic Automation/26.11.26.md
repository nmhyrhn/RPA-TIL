# [UiPath Agentic Automation] Maestro Case와 Maestro Flow

## 오늘 정리한 내용

고객 문의를 예로 생각하면 Case의 구조가 이해하기 쉽다. 문의 한 건에 원문, 분류 결과, 담당자 정보를 모아 두고, 접수나 분류 같은 큰 단계는 Stage로, 각 단계 안에서 할 일은 Task로 구성한다. Rule은 현재 상태와 데이터에 따라 어떤 단계로 넘어갈지 정한다.

Flow는 에이전트, API, RPA처럼 실행할 작업을 노드로 연결하는 방식이다. 문의 요약 예시에서는 어떤 노드가 원문을 받고, 생성된 요약이 어느 노드로 넘어가는지를 중심으로 보면 된다.

## 대표 실습 — 고객 문의 분류 Case

- 시작 조건 — 문의 텍스트를 트리거로 받고, 분류 에이전트의 유형·우선순위·요약·신뢰도 출력을 Case 필드에 연결한다.
- 정상 경로 — 접수 → 분류 → 담당자 배정 → 종료 및 결과 저장.
- 예외 경로 — `confidence < 0.7`이면 수동 분류 단계로 보내고, 담당자가 결과를 입력하면 분류 단계로 돌아간다.
- 재진입 설정 — 분류 Task에 Run Once를 적용해 자동 분류가 다시 실행되어 수동 결과를 덮어쓰는지 점검한다.
- 시간 확인 — 단계별 SLA 기준과 초과 시 알려야 할 담당자를 정한다.

## 응용 실습 — 문의 요약 Flow

```text
Trigger → 문의 텍스트 전달 → 요약 Agent → 출력 매핑 → 결과 반환
```

Trigger로 실행을 시작하고, Edge로 노드의 실행 관계를 연결한다. 입력과 노드 출력이 어디에 매핑되는지 Variables에서 확인하고, 외부 서비스가 필요한 노드의 연결은 Bindings에서 확인한다. 요약 결과에 Mock 값을 넣으면 에이전트를 호출하기 전에 다음 노드가 값을 제대로 받는지 살펴볼 수 있다. 이후 실제 응답을 넣었을 때도 같은 경로로 값이 전달되는지 비교하면 된다.

## 구성 메모

| 구성 | 설계 기준 | 예시 |
|---|---|---|
| Maestro BPMN | 정해진 절차와 조건별 분기 | 구매 승인 |
| Maestro Case | 건별 상태, 단계, 처리 규칙 | 문의 분류와 수동 검토 |
| Maestro Flow | 노드 연결과 데이터 전달 | 요약 Agent와 API 연결 |

## 증상별 점검

- 신뢰도가 경계값일 때 경로가 헷갈림 — 조건이 `confidence < 0.7`이면 0.7인 문의는 수동 분류 조건에 해당하지 않는다.
- 낮은 신뢰도인데 담당자에게 넘어가지 않음 — 신뢰도 값의 형식과 분류 Stage 종료·수동 분류 Stage 진입 규칙을 확인한다.
- 수동 분류 후 결과가 덮어써짐 — 재진입 조건과 분류 Task의 Run Once 설정을 확인한다.
- 담당자 배정 후 Case가 끝나지 않음 — 필수 Task 완료 여부와 Closure 진입 조건을 확인한다.
- Flow의 다음 노드에서 값이 비어 있음 — 앞 노드 출력, 변수 매핑, Mock의 출력 형식을 확인한다.

## 오늘의 정리

Case를 복습할 때 기억해 둘 예외는 수동 분류 뒤 이전 단계로 돌아오는 상황이다. 이때 Run Once가 적용된 분류 작업의 실행 이력과 수동으로 입력한 분류 값이 유지되는지 확인할 수 있다. Flow에서는 앞 노드의 출력을 다음 노드가 제대로 받는지 한 단계씩 따라가면 된다.
