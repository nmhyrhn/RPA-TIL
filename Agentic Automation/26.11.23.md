# [UiPath Agentic Automation] Integration Service와 GenAI 액티비티

## 오늘 정리한 내용

Integration Service를 정리하면서 커넥터와 연결(Connection)을 구분해 두었다. Gmail 커넥터는 메일 조회나 발송처럼 사용할 수 있는 기능을 제공하고, 연결은 그 기능을 어느 계정과 권한으로 쓸지 정한다. 이벤트 트리거는 연결된 계정에서 새 메일처럼 지정한 이벤트가 감지됐을 때 게시된 프로세스를 시작한다.

기본 커넥터에 필요한 기능이 없다면 먼저 외부 서비스가 해당 작업을 API로 제공하는지 살펴볼 수 있다. API가 있다면 Connector Builder에서 인증 방식과 요청·응답 구조를 정의할 수 있는지 확인하면 된다.

## 대표 실습 — Gmail 이벤트로 자동화 시작

- 시작 조건 — 테스트용 Gmail 연결을 만들고 Studio Web 프로세스를 게시한다.
- 구성 — Orchestrator에서 이벤트 트리거를 만들고 연결, 감지할 이벤트, 실행할 프로세스, 런타임을 지정한다.
- 테스트 — 제목에 `요청`을 넣은 메일과 해당 단어가 없는 메일을 각각 보낸다.
- 예상 결과 — 조건에 맞는 메일에 대해 작업이 시작되고, 일치하지 않는 메일은 실행 이력을 만들지 않는다.

```text
Gmail 연결 → 새 메일 수신 → 제목 조건 확인 → 프로세스 실행 → 작업 이력 확인
```

## 응용 실습 — 받은 내용을 요약하거나 번역하기

메일에 회신이 필요한지 빠르게 파악하려면 Content Generation에 본문과 함께 ‘요청 사항과 마감일을 포함해 두 문장으로 요약’이라고 지시할 수 있다. 영문 상품 설명을 Translate에 전달할 때는 제품명과 수치가 그대로 남는지 보는 게 좋겠다. 첨부 이미지의 내용을 파악하는 예시라면 Storage Bucket에서 파일을 내려받아 Image Analysis의 입력으로 넘긴다.

## 액티비티 메모

| 작업 | 액티비티 | 전달할 데이터 |
|---|---|---|
| 메일 요약 | Content Generation | 본문과 요약 지시 |
| 이미지 가져오기 | Download Storage File | 버킷과 파일 경로 |
| 이미지 내용 파악 | Image Analysis | 내려받은 이미지와 질문 |
| 상품 설명 번역 | Translate | 원문과 대상 언어 |

## 증상별 점검

- 이벤트 실행 이력이 없음 — 연결 계정, 트리거 활성화 상태, 필터, 게시된 프로세스를 확인한다. 이벤트 감지에 걸리는 시간도 고려한다.
- 트리거가 메일을 감지했는데 작업이 시작되지 않음 — 이벤트 감지 기록과 Orchestrator 작업 이력을 대조해, 이벤트 수신 뒤 프로세스가 호출됐는지 확인한다.
- 작업은 시작됐지만 실패함 — 실행 로그에서 런타임과 액티비티 연결 오류를 확인한다.
- 이미지 분석 입력이 비어 있음 — 다운로드 결과와 다음 액티비티의 입력 매핑을 확인한다.
- 요약에서 마감일이 사라짐 — 프롬프트에 남겨야 할 항목을 명시하고 같은 입력으로 다시 비교한다.

## 오늘의 정리

Gmail 예시를 다시 볼 때는 계정 연결, 이벤트 감지, 프로세스 실행을 순서대로 따라가면 어디에서 문제가 생겼는지 찾기 쉽겠다. 요약이나 번역 결과를 후속 작업에 쓸 때는 요청 사항, 날짜, 수치처럼 꼭 필요한 값이 남아 있는지도 확인할 부분이다.
