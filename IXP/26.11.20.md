# [UiPath IXP] Studio에서 DU 분류·추출·검증·내보내기 연결

## 1. 학습 주제

오늘은 Studio에서 Document Understanding 프로젝트를 호출하고 사람이 확인한 결과를 Excel로 저장하는 흐름을 정리했다. 액티비티 이름을 외우기보다 앞 단계에서 만든 값이 다음 단계 어디에 들어가는지를 따라갔다.

## 2. Taxonomy에서 결과 필드 정의

Taxonomy 관리자는 그룹, 카테고리, 문서 형식, 필드를 구성하는 곳이다. 예를 들어 회계 그룹의 매입 카테고리에 송장 유형을 두고 송장번호, 발행일, 총액을 정의할 수 있다. `Load Taxonomy`를 실행하면 설정을 분류와 추출에서 사용할 변수로 가져온다.

프로젝트를 구성할 때는 입력 문서 경로와 출력 폴더를 변수로 관리한다. 같은 워크플로우에 다른 문서를 넣어 흐름을 비교하기 쉽고, 결과 경로가 문서 읽기 로직에 섞이지 않는다.

## 3. 액티비티별 입출력

| 단계 | 액티비티 | 다음으로 넘기는 값 |
|---|---|---|
| 준비 | Load Taxonomy | 문서 유형과 필드 정의 |
| 디지털화 | Digitize Document | 전체 텍스트와 위치 정보를 담은 문서 개체 모델 |
| 분류 | Classify Document Scope | 분류 결과 |
| 분류 검증 | Present Classification Station | 검토한 문서 유형 |
| 추출 | Data Extraction Scope | 추출된 필드와 값 |
| 추출 검증 | Present Validation Station | 사람이 확인하고 수정한 추출 결과 |
| 내보내기 | Export Extraction Results | 결과 테이블이 들어 있는 DataSet |

분류 검증에서는 문서 유형을 확인하고, 추출 검증에서는 해당 유형의 필드값을 확인한다. 발행일과 지급기한이 서로 바뀌었다면 추출 검증에서 원문을 보고 수정한다. 검증 단계를 거쳤다면 Export에는 수정이 반영된 결과 변수를 연결한다.

## 4. Classic과 Modern 연결

Classic 흐름에서는 `Intelligent Keyword Classifier`나 `Machine Learning Extractor`처럼 용도에 맞는 액티비티를 Scope 안에 지정한다. 학습 데이터를 수집하는 흐름을 구성했다면 사람이 교정한 결과를 `Train Classifiers Scope` 또는 `Train Extractors Scope`에서 해당 Trainer로 넘긴다.

Modern 프로젝트를 연결하는 흐름에서는 `Document Understanding Project Classifier`와 `Document Understanding Project Extractor`에서 프로젝트를 선택한다. Studio의 Taxonomy 유형과 프로젝트 유형, 필드 간 매핑을 확인해야 한다. 모델이 찾은 값이 있어도 매핑이 누락되면 워크플로우가 기대한 필드는 비어 있을 수 있다.

## 5. 검증 결과를 Excel로 저장

```text
검증된 ExtractionResult
→ Export Extraction Results
→ DataSet.Tables 순회
→ 각 DataTable을 Result_01, Result_02 등의 시트에 기록
```

DataSet에는 여러 DataTable이 들어갈 수 있다. 일반 필드와 품목 표가 어떻게 나뉘어 들어왔는지 테이블 이름과 열을 확인하고, 반복문에서 시트 번호를 증가시킨다.

```vb
"Result_" & tableIndex.ToString("00")
```

## 6. 복습 메모

결과 파일이 비어 있다면 PDF에서 텍스트가 읽혔는지, 분류 유형이 맞았는지, 필드가 매핑됐는지, Export가 검증된 결과를 받았는지 차례로 본다. 같은 송장으로 발행일을 한 번 수정해 보는 시나리오를 생각하면 검증 결과 변수의 역할이 분명해진다.
