# [UiPath IXP] 계약서 필드 추출과 Agent Builder 연동

## 1. 학습 주제

오늘은 교육 계약서를 예로 들어 IXP에서 필요한 값을 추출하고, Agent가 그 값으로 검토 사항과 실행 목록을 만드는 흐름을 정리했다. 추출 필드와 후속 업무에서 필요로 하는 출력 항목을 먼저 잡아 봤다.

## 2. 템플릿과 직접 구성

| 시작 방식 | 구성 흐름 |
|---|---|
| 템플릿 | 기존 필드 확인 → 샘플 추가 → 예측 검토 → 필요한 필드 조정 |
| 직접 생성 | 문서에서 필요한 값 정의 → 필드와 예측 설정 → 샘플 추가 → 주석 제출 |

두 방식 모두 필드별 예측을 원문과 비교한다. 계약 기간과 교육 실시 기간처럼 이름이 비슷한 값은 뜻을 구분해 필드 설명을 작성한다. 총액에 부가세가 포함됐는지처럼 확인이 필요한 내용은 원문 표기를 기준으로 본다.

샘플에서 추출한 값이 맞으면 확인하고, 누락되거나 잘못 선택된 값은 수정해 주석을 제출한다. 측정 결과에서 반복적으로 틀리는 필드를 확인하고, 실제 호출에 쓸 프로젝트 버전을 Deploy한다. 연결 전에 사용할 버전이 라이브 상태인지 확인한다.

## 3. 계약서의 추출 필드 예시

| 필드 | 원문에서 확인할 기준 |
|---|---|
| 계약 당사자 | 발주자와 수행자 명칭을 각각 식별 |
| 교육 기간 | 실제 교육 시작·종료일과 계약 기간을 구분 |
| 교육 인원 | 확정 인원과 예상 인원이 있다면 구분 |
| 계약금액 | 전체 계약금액과 분할 지급액을 구분 |
| 지급 조건 | 지급 기한, 청구 조건, 제출 서류 확인 |

같은 항목이 계약서 본문과 별첨에 모두 나오면 문서 안에서 값이 일치하는지 검토 대상으로 남길 수 있다. 예를 들어 본문 정원과 별첨 운영표의 인원이 다르면 담당자가 확인할 사항으로 이어진다.

## 4. Studio에서 IXP 추출 결과 받기

```text
Load Taxonomy
→ Digitize Document
→ Data Extraction Scope + Document Understanding Project Extractor
→ Present Validation Station
→ Export Extraction Results
```

Project Extractor에서 사용할 프로젝트와 버전을 연결한다. `ReferenceDocumentId`는 문서 식별자이고, 실제 필드값은 Scope에서 받는 추출 결과에 담긴다. 사람이 수정한 내용을 Excel에 반영하려면 검증 결과를 Export에 연결한다.

## 5. Agent Builder에서 입출력 정의

Agent는 계약서 파일을 입력으로 받고 IXP 도구로 필드값을 가져온다. 프롬프트에는 추출된 값을 기준으로 요약과 실행 항목을 작성하고, 값이 빠지거나 서로 다르면 확인 근거를 남기도록 역할을 지정한다.

| 인수 | 타입 | 역할 |
|---|---|---|
| document | File | 검토할 교육 계약서 한 건 |
| summary | String | 당사자, 일정, 인원, 금액 요약 |
| reviewNotes | String | 확인할 사항과 관련 근거 |
| actionPlan | String | 교육 준비 및 정산에 필요한 작업 |
| needsHumanReview | Boolean | 중요 정보 누락, 불일치, 추가 협의 필요 여부 |

예를 들어 지급일이 비어 있고 계약서에는 검수 완료 후 지급이라고만 적혀 있다면, 요약에는 확인된 지급 조건을 적고 검토 사항에는 구체적인 지급일 확인을 남긴다. `needsHumanReview`는 `True`로 반환하도록 설계할 수 있다.

## 6. 복습 메모

IXP에 맡길 필드는 원문에 있는 정보를 중심으로 정의한다. Agent의 출력에는 그 값을 엮어 어떤 일정과 서류를 확인해야 하는지 담는다. 값이 모두 있는 문서, 필수 값이 빠진 문서, 본문과 별첨 값이 다른 문서를 각각 넣어 보면 추출과 검토의 연결을 점검하기 좋다.
