# [UiPath IXP] IXP와 Document Understanding의 기본 흐름

## 1. 학습 주제

오늘은 PDF나 이메일처럼 바로 업무 시스템에 넣기 어려운 데이터가 어떤 단계를 거쳐 자동화에 쓰이는지 정리했다. 송장 한 장을 기준으로 글자를 읽는 작업, 필요한 값을 고르는 작업, 사람이 결과를 확인하는 작업을 나눠서 봤다.

## 2. IXP, OCR, IDP, DU의 역할

| 용어 | 역할 | 예시 |
|---|---|---|
| IXP | 문서나 커뮤니케이션에서 필요한 정보를 구조화 | 계약서에서 계약 기간과 지급 조건 추출 |
| OCR | 이미지에 있는 글자를 텍스트로 인식 | 스캔 이미지에서 날짜와 숫자 읽기 |
| IDP | 문서 분류, 필드 추출, 검증을 포함하는 지능형 문서 처리 방식 | 송장을 분류하고 승인에 필요한 값 정리 |
| Document Understanding(DU) | UiPath에서 문서 처리 흐름을 구성하는 기능 | 읽어온 송장에 추출기를 적용하고 검증 결과 전달 |

OCR 결과에 날짜가 세 개 있더라도 어떤 날짜가 발행일인지는 별도로 판단해야 한다. 송장번호, 발행일, 지급기한처럼 업무에서 사용할 이름을 붙이는 단계가 필드 추출이다.

## 3. 문서 유형에 따른 접근

| 문서 유형 | 특징 | 확인할 부분 |
|---|---|---|
| 정형 | 같은 양식에서 값의 위치가 일정함 | 같은 영역에 값이 들어가는지 확인 |
| 반정형 | 필요한 항목은 비슷하지만 배치와 표기 방식이 달라짐 | 여러 공급사의 양식과 항목명 변형을 포함 |
| 비정형 | 내용이 문단이나 문장에 흩어짐 | 문장이나 조항의 문맥으로 추출 기준 정의 |

공급사마다 송장 레이아웃이 다르면 좌표만으로 값을 찾는 방식은 유지하기 어렵다. 계약서에서는 금액이 여러 번 등장할 수 있어서 총 계약금액과 선금처럼 의미부터 구분해야 한다.

## 4. 문서 처리 기본 흐름

```text
입력 문서
→ 디지털화: 텍스트와 위치 정보 확보
→ 분류: 문서 유형 판단
→ 추출: 유형에 맞는 필드값 식별
→ 검증: 원문과 결과를 비교하고 필요하면 수정
→ 내보내기: 확인한 값을 후속 업무에 전달
```

분류가 틀리면 다른 유형의 필드 구성이 적용될 수 있다. 예를 들어 발주서를 송장으로 분류하면 번호 형식이 비슷해도 송장번호에 발주번호가 들어갈 수 있다. 결과를 볼 때는 어떤 유형으로 분류됐는지부터 확인하는 편이 이해하기 쉬웠다.

## 5. UiPath 구성 요소 연결

| 구성 요소 | 맡는 일 |
|---|---|
| Automation Cloud의 DU 프로젝트 | 문서 유형과 필드 구성, 모델 성능 확인 및 게시 |
| Studio | 입력 파일부터 결과 저장까지 워크플로우 연결 |
| Validation Station | 추출 결과를 원문과 대조하고 수정 |
| Orchestrator와 Action Center | 사람 검토가 필요한 자동화 작업을 운영하는 데 활용 |

## 6. 복습 메모

문서가 잘 읽혔는지, 문서 유형이 맞는지, 각 값이 올바른 필드에 들어갔는지 순서대로 확인한다. 송장번호처럼 결과가 그럴듯해 보이는 값도 원문에서 어떤 항목에 연결됐는지 확인해야 한다.
